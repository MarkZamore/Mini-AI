# Локальная база документов Satbayev University

JSON документов и SQLite-поиск предназначены для локального исследовательского окружения. Оригиналы расположены рядом, в `../docs`; конвертер их не изменяет. Документы не отправляются внешним OCR или языковым сервисам.

## Запуск из любой папки

В этой установке используйте Python:

`C:\Users\Oscar\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`

Поиск:

```powershell
& 'C:\Users\Oscar\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' 'C:\Users\Oscar\Documents\EnterpriseAI\db\search.py' --db 'C:\Users\Oscar\Documents\EnterpriseAI\db' search 'академическая политика' --limit 10
```

Результат — JSON-массив с текстом, ID фрагмента и документа, хешем версии, `source_refs`, качеством и предупреждениями. Повторное OCR при поиске не запускается. Доступ к SQLite открывается только на чтение.

Меньшее значение `score` означает более высокую релевантность (соглашение SQLite BM25). В результатах приведены предупреждения конкретного фрагмента и отметка общего неполного извлечения документа; полный перечень находится в его каноническом JSON.

Python-интерфейс:

```python
import sys
sys.path.insert(0, r'C:\Users\Oscar\Documents\EnterpriseAI\db')
from search import Database

with Database(r'C:\Users\Oscar\Documents\EnterpriseAI\db') as base:
    hits = base.search('академическая политика', limit=10)
    if hits:
        fragment = base.get_fragment(hits[0]['fragment_id'])
        source = base.resolve_source(fragment['source_refs'][0])
```

`neighbors(document_id, relation=None, limit=20)` возвращает входящие и исходящие подтверждённые связи. Неоднозначные ссылки сохранены в SQLite и JSON, но не выдаются за подтверждённые рёбра.

CLI также поддерживает `get FRAGMENT_ID`, `neighbors DOCUMENT_ID`, `resolve LOCATOR_JSON` и `rebuild`. Аргумент `--db` указывается до команды.

## Повторная обработка и проверка

Для продолжения текущего набора с тем же отпечатком конвертации используйте `run_batch.py --workers 10`. Планировщик меняет только параллелизм; модели, параметры OCR и уже опубликованные результаты сохраняются. На этом ноутбуке десять рабочих процессов используют запас 16 ядер и 32 ГБ памяти; нагрузка сначала проверена на шести процессах. OpenCV ограничен одним потоком на процесс, чтобы избежать конкуренции за ядра. Более крупные оставшиеся документы запускаются первыми. Отдельные этапы восстановления текста из сохранённых результатов OCR и построения индекса выполняются после конвертации. Повторное использование проверяется окончательной полной проверкой оригиналов и артефактов; наличие JSON само по себе не означает успешную проверку базы.

```powershell
& 'C:\Users\Oscar\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' 'C:\Users\Oscar\Documents\EnterpriseAI\db\convert.py' --db 'C:\Users\Oscar\Documents\EnterpriseAI\db'
& 'C:\Users\Oscar\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' 'C:\Users\Oscar\Documents\EnterpriseAI\db\validate.py' --db 'C:\Users\Oscar\Documents\EnterpriseAI\db'
```

`--ids 46539 27101` ограничивает пакет документами; `--force` требует повторной обработки; `--skip-index` оставляет перестроение поиска отдельной операцией. Ключ повторного использования включает оригинальный SHA-256, схему, код, инструменты, модели и настройки. Подходящий результат сначала валидируется, включая хеши производных файлов. Неудачная замена сохраняет прежний пригодный JSON. `catalog.json` и `report.json` описывают текущий результат и перезаписываются; истории операций в них нет.

## Схема и происхождение

Схема: `schema/document.schema.json`, версия 1.0, JSON Schema 2020-12. Пути считаются относительно корня базы; исходный файл указывается как `../docs/раздел/имя`. ID документа зависит от идентификатора университетского источника, а SHA-256 определяет его версию. ID блока стабилен только внутри этой версии и конфигурации извлечения.

`source_refs` указывает оригинал или сохранённый производный артефакт. PDF: страницы от 1, координаты в пунктах, начало сверху слева. DOCX: часть ZIP и XPath с пространствами имён из исходного XML. Для DOC/RTF XPath относится к производному DOCX; он не означает положение в исходном бинарном DOC. Excel: имя листа, диапазон либо рисунок с XML-адресом и якорями. Диапазоны текста: Unicode-кодовые точки, начало включительно, конец исключительно.

Таблицы содержат ячейки и объединения. XLSX хранится разреженно: пустые ячейки с одним форматированием не создают сотни тысяч записей. Формулы и сохранённые результаты разделены. Для старого XLS значения берутся из оригинала; выражения формул и рисунки дополнительно извлекаются из производного XLSX с явной привязкой к нему.

Завершающий этап `enrich.py` добавляет в JSON XLSX исходные числовые форматы, стили и систему дат. Числовой сериал даты остаётся в `value`; ISO-представление без добавленного часового пояса хранится в `payload.cell_formats` и используется в поисковом представлении. Версия и SHA-256 этого этапа записаны отдельно в `extraction.tools.excel_display_metadata`; повторное построение индекса его не повторяет при совпадающем отпечатке. `--skip-index` также откладывает этот завершающий этап.

Для XLS действует тот же каталог форматов и единая система дат 1900/1904. Типы ячеек XLS/XLSX приводятся к общим именам (`string`, `number`, `boolean`, `error`, `excel_date_serial`, `iso_date`); исходный тип сохраняется в каталоге форматов.

Завершающий этап `repair_ocr.py` проверяет текст по исходным TSV Tesseract. Кавычки здесь являются символами распознанного слова, а не CSV-разметкой. Если ранний разбор отличался, текст и координаты восстанавливаются из сохранённого вывода, при необходимости повторно выбирается вариант OCR и восстанавливается соответствующее изображение. Нейросетевое распознавание для этого не повторяется. Хеш этого этапа записан в `extraction.tools.quote_safe_tsv_parser`; прежние исходные данные OCR сохраняются.

## OCR и ограничения достоверности

OCR выполняется локально Tesseract LSTM с `tessdata_best` (rus/kaz/eng). Все оценки относятся к распознаванию, а не к вероятности истинности текста. Непроверенный текст остаётся `machine_extracted`. Сомнительные результаты включаются в поиск вместе с предупреждениями и исходными координатами.

Исходное извлечение PDF и полные варианты OCR сохраняются раздельно. Условие повторной обработки: средняя уверенность ниже 90 или более 10% слов ниже 60. Начальное разрешение 300 DPI; повтор — 400 DPI. Для PDF с необычно большой физической страницей длинная сторона изображения ограничена 4200/5600 пикселями; масштаб обратно к оригинальной странице хранится в OCR evidence. Этот предел предотвращает избыточное увеличение уже сканированного изображения.

`complete` означает отсутствие известных пропусков обработки, но не человеческую проверку OCR. `partial` означает пригодный результат с перечисленными ограничениями. `failed` содержит конкретную диагностику. Вся ручная корректировка текста должна сопровождаться сохранением исходного распознавания и отдельной отметкой проверки; текущий конвертер текст не переписывает.

Разметка PDF и восстановленные таблицы основаны на геометрии и требуют проверки при сложной вёрстке. Нераспознаваемые изображения и вложения сохраняются. Формулы Excel не пересчитываются; отсутствующие сохранённые результаты помечаются. Визуализация графа, векторный индекс и синхронизация сайта в текущий этап не входят.

## Проверка OCR человеком

Откройте изображение `page_render`, указанное в OCR evidence, локально и сопоставьте текст с источником. При низкой уверенности дополнительно сравните 300/400 DPI варианты. `report.json` содержит `human_ocr_review_performed: false`, пока реальная ручная сверка не выполнена. Конвертер не выдаёт машинную оценку за ручную проверку.

## Зависимости

Изолированные инструменты и модели: `_runtime`; версии, URL и SHA-256 записаны в `_runtime/tools.json`. Системный LibreOffice и пользовательский профиль не используются. Преобразование запускается через частный локальный UNO pipe с запретом макросов и обновления внешних связей, с отключением обновления Writer-полей и автоматического пересчёта Calc.

При переносе базы сохраняйте расположение `db` и `docs` рядом. Поиск использует стандартный SQLite и локальный Snowball. Для конвертации на другом компьютере потребуется подготовить Python-зависимости и указать доступные локальные исполняемые файлы в `_runtime/tools.json`.
