# Пилот новых source-free task-эталонов

**12 авторских примеров:6RU/6KZ. Статус: `PENDING_INDEPENDENT_AUTOMATIC_SEMANTIC_REVIEW`. Для обучения не утверждены.** Это составление полезного текста по фактам самого пользовательского запроса; примеры не изображают реальные происшествия и не являются нормативным QA по университетской базе.

Сценарии: ответ на приглашение с неизвестной позицией; обращение по неполадке домашнего принтера; отчёт об опыте с фасолью; уведомление о переданном оборудовании киноклуба; ответ о выбранной теме плаката; неполная посылка; ответ о разрешении публикации фотографии; инвентаризация домашних спортивных вещей; сообщение соседу о выполненном поливе; предложение перенести встречу учебной группы; заполняемый читательский дневник; запрос предварительного заказа в кафе.

`family_ids`, `document_ids`, `source_ids`, `sources` пусты. Каждому самостоятельному сценарию назначен source-free group ID. Это не переводные/подставленные варианты прежнего action14 и не фиктивная привязка к train-семействам корпуса. Не использованы сами demo5, нормативные targets открытого development или закрытые тестовые вопросы. Независимый reviewer ещё должен проверить смысловую удалённость и пригодность каждого сценария.

В `pilot-rows.jsonl` находятся вопрос, target, типизированный ledger ролей/известных фактов/неизвестных полей, запреты и точные model messages. Ledger — **только audit-метаданные**, модель его не получает. В `messages-pending-review.jsonl` только обычные system/user/assistant сообщения и служебные метки статуса; дополнительного oracle-input нет. `questions.jsonl` и `targets.jsonl` облегчают отдельную проверку.

`PreparePilot.java` построил вход **точно как первая попытка `AssistantModule.taskProposal`**:

- system = `TaskSolution.system()` + перевод строки + `TaskSolution.instruction(analyzedKind)` + текущая языковая инструкция приложения;
- user = `TaskSolution.prompt(question, analyzedKind, emptySources, new CitationAliases(emptySources, true))`;
- target = полный авторский текст самого предлагаемого проекта.

Тип и язык получены реальным `AssistantIntent.analyze`, без ручной подмены. Все12 являются текущими editable source-free видами и прошли текущий `TaskSolution.validate` на полном семимодульном JVM-classpath. **Это проверка формального validator, а не доказательство всей семантики.** Исходники helper и production-файлов, classpath provenance и SHA outputs закреплены в `preparation-manifest.json`. Продуктовые файлы не менялись; модель, GPU, GUI и полный Session-run не запускались.

Для будущего SFT предусмотрен response-only контракт: loss только по assistant-target. Токенизация, prefix mask, лимит длины и экспорт ещё не подготовлены/не проверены; настоящего обучения не было. Train/dev split этому ограниченному authoring-пилоту ещё не назначен. Его нельзя описывать как выполненное разбиение до составления targets. Любое будущее разбиение и общий train-manifest должны быть зафиксированы до обновления весов и просмотра новых model outputs; связанные языковые/контрфактуальные варианты остаются в одной группе.

При неоднозначности reviewer отмечает `unknown`/exclude; число12 не является требованием принять все12. Исправления после review необходимо версионировать, сохраняя проверенную исходную версию и SHA. Одобрение формата не означает подтверждённого улучшения модели: понадобится отдельное сравнение с исходной моделью на тех же входах и лимитах.
