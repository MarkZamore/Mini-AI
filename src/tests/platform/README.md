# Реальный тест WindowsPlatform

Подготовка: собрать enterpriseai-platform.dll штатной сборкой, затем выполнить prepare-fixture.ps1. Скрипт собирает маленький C-исполнитель с автономной C-runtime в src/build/test-results/platform-fixtures и копирует туда готовую библиотеку платформы. Никакие файлы модели или существующей базы не изменяются.

NativePlatformTest запускается из готовых testClasses с классами приложения и SDK GraalVM на classpath. Аргумент — папка src; если запуск выполняется из неё, указать точку. Для JVM включить native-access, отключить perfdata/attach/core/heapdump и направить ErrorFile в NUL, как в профиле приложения. Испытательные инструменты вправе записывать свои отчёты в src/build.

Проверяются реальные JNI-вызовы: путь фактического процесса, физическая память, CPUID, анонимные UTF-8 каналы, отсутствие console window, нормальное завершение, кооперативная отмена, принудительное завершение зависшего процесса, ошибочный выход 42, отказ выделения 128 МиБ при Job-пределе 32 МиБ, уничтожение дочернего дерева при закрытии Job, повторные запуски, отсутствующий EXE, Unicode/длинный путь исполнителя, запуск из длинной папки данных, завершение забытого worker при закрытии платформы и изоляция каналов/Job при параллельном запуске двух независимых экземпляров платформы.

Отчёт native-platform-test-report.json содержит пройденные сценарии, completed и failure. Исполнитель не открывает файлы и не обращается к сети/реестру. Проверка не заменяет Process Monitor, загрузку настоящей модели или приёмку на чистой Windows. Сценарий ошибочного завершения использует ExitProcess(42), а не реальную access violation.

Windows не позволяет CreateProcessW создавать процесс с текущей папкой длиннее MAX_PATH; это подтверждено испытанием и [документацией Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setcurrentdirectory). Поэтому для длинной папки данных платформа выбирает короткую System32, полученную через Windows API. EXE запускается по исходному абсолютному длинному пути; относительные пути worker обязан считать от собственного EXE и manifest, а не от cwd. Тест проверяет и успешную генерацию фикстуры, и этот явный fallback, без копирования данных во временный каталог.
