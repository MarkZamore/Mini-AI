Взяты заранее зафиксированные позиции `0,3,8,11,15` из `generator/data/generation-messages.jsonl`, SHA-256 `6584f3082dee74873add607a5ebbe841fbd8c307b1106df9deb29ab728e5ce91`. Для обоих backend одинаковы исходные сообщения, лимиты ответа 116/106/173/96/96, входы 425/418/483/355/331 токенов, Qwen3.5-4B baseline Q6_K, context 8192, 12 threads и greedy sampling. CPU использует проверенный AVX2 Haswell backend той же полной поставки. EXE в обоих опытах одинаковый: `9eb3fd03c49d08ccad99112c1f1876f7cba5cab52aa87e1ffb7eb5852573f6cb`.

Каждый вопрос запускает свежий процесс. Файловый кеш не сбрасывался: термин «disk cold» неприменим. CPU-окно прошло после окончания обучения, экспорта, индексирования и оценок других агентов. Опыты последовательные, порядок не рандомизирован, повторов и доверительных интервалов нет. CUDA-резерв — 3 GiB.

## Повторное использование v2 и реальный Job Object

Полная текущая композиция из семи модулей, настоящий `WindowsPlatform`, context 16384, Job Object max 8 GiB / min free 9 GiB, CUDA reserve 3 GiB. Окончательный EXE после исправления evidence lifecycle и повторной проверки свободного резерва перед каждым generate: `471294bf47db369cb6d4c23c375ba1455db38f75945a43f159c0d793d071b5ff`.

11/11 проверок: два независимых запроса в одном процессе; cancel закрывает процесс; следующий запрос создаёт новый; manifest удерживается native read-only и не заменяется при живом процессе; после внешнего завершения и изменения manifest требуется fresh validation; ошибочный manifest отвергается; закрытие context завершает все worker.

После этой проверки evidence-only maxLength BGE выровнен с калибровкой на 256. Новая итоговая сборка: `60b57752154f6f1b8104c1d8880c9bc6551dda072db59b5dcce6ff6bd84e4ff8`; код генерации не менялся. Evidence parity/lifecycle для этой сборки проверяются отдельно основным агентом.

Для коротких арифметических запросов wall → первый текст: первый 9.367 с, второй 0.024 с; после cancel новый процесс 8.413 с. Это проверка reuse/transport, не контролируемый прогноз скорости нормативного ответа; фоновые действия и файловый кеш между этими запросами не выравнивались. Wire JSONLv1 прежний, native очищает память контекста перед каждым generate, v1 сохраняет отдельный процесс на запрос. Отчёт: `gpu-worker/persistent-test/result.json`.

GPU memory diagnostics показывают глобальную свободную память устройства и её изменение относительно старта. Это не process-exclusive peak VRAM и не аппаратная квота против будущих выделений Windows/Teams. Проверка с реально открытым Teams и финальным GUI выполняется отдельно.
