# Model worker v2

Один Windows x64 EXE обслуживает генерацию `enterpriseai.inference.v1` и, при включённом evidence-коде, `enterpriseai.evidence.v1`. Для обоих используется `--stdio`; режим выбирается первым bounded `hello`. Java-приложение не запускает сервер и не требует установленного Python, Java или CUDA Toolkit.

Подготовка выполняется отдельно, обычным пользователем. Требуются существующие MSVC/Windows SDK, CMake и Python подготовки. Скрипты не устанавливают системные компоненты и не запрашивают UAC.

```powershell
& ./src/model-worker/Prepare.ps1 -EnableEvidence
& ./src/model-worker/Package.ps1 -EnableEvidence
```

По умолчанию результаты находятся в `src/build/research-20261024/gpu-worker`. Корневые EXE, модель, docs и db эти команды не изменяют. Выходной комплект нужно квалифицировать отдельно перед публикацией. `Package.ps1` использует hard link к исходным неизменным весам, не создавая второй полный файл на том же томе.

## Фиксация зависимостей

llama.cpp: release `b11669`, commit `620d2225cc436ab0b001e3200e590e3b286ef9ab`. Официальные Windows CUDA 12.4 DLL используются без изменения. Import libraries генерируются из их экспортов; wrapper компилируется против заголовков и исходников того же commit без nvcc. SHA исходного ZIP и двух бинарных архивов закреплены в `Prepare.ps1`. Нельзя смешивать другую ревизию заголовков с этими DLL.

Evidence: ONNX Runtime CPU 1.31.0 и SentencePiece 0.2.2 из общей папки `research-20261024/dependencies`. Абсолютные пути подготовки не входят в manifest модели. Статические SentencePiece/Abseil используют `/MT`. Для обычного пользователя каталог `third_party/absl` копируется вместо требующего привилегий symlink. В поставку включаются лицензии и notices этих библиотек.

## Границы контракта

Manifest v1 и его прежний standalone worker продолжают поддерживаться приложением. Новый worker использует manifest v2: один EXE, все веса/данные в `files`, только перечисленные с SHA DLL в `runtime/` и отдельный explicit backend. Локальные DLL загружаются после проверки полного inventory; delay imports исключают их неявную загрузку до проверки. CPU/CUDA backends выбираются по проверенным абсолютным путям, не сканируются PATH/сеть. Файлы inventory удерживаются открытыми без разрешения записи/удаления на время работы.

CUDA-профиль проверяет свободную VRAM до загрузки и после создания контекста. По умолчанию бюджет 8 GiB и свободный резерв 3 GiB; это критерий допуска, а не аппаратная квота против будущих выделений Teams/Windows. При нехватке ресурсов worker выдаёт ошибку и не меняет backend незаметно. `maxProcessMemoryBytes` ограничивается host через Job Object и не является лимитом VRAM.

Проверка PE не доказывает отсутствие любых динамических загрузок. Логи/кеши Windows, CUDA-драйвера и сторонних библиотек не покрываются прежним обещанием полностью статического CPU-комплекта; обязательная трассировка Process Monitor исключена пользователем.

## Свидетельства

`probe_gpu.py` берёт общий exclusive GPU lease, проверяет реальный короткий арифметический запрос, сохраняет frames, истинный TTFT и ограниченный stderr. Это проверка транспорта и GPU offload, не подтверждение качества нормативных ответов или GUI. `tests/ManifestV2Test.java` проверяет принятие реальных комплектов v1/v2 и отклонение недопустимых manifest, не запускает модель. `latency_pilot.py` и `compare_generators.py` сохраняют ограниченные development-пилоты с actual input/output counts; интерпретация и границы измерений приведены в `RESEARCH_RESULTS.md`. `tests/run_persistent_test.py` запускает проверку полного состава приложения на настоящем Windows Job Object.
