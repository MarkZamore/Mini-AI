# Дельта-доставка Mini-AI

`delta.py plan` проверяет состав изменений без создания архивов. `delta.py build` реализован для будущего утверждённого полного приложения: создаёт малый установочный ZIP, ZIP только изменённых runtime-файлов, SHA256SUMS и publication-assets.json. **Сборка пакета и установка ещё не выполнялись.** Базовые проверки файловых операций не являются проверкой установщика. Публикация, продвижение runtime и создание Git tag этими командами не выполняются.

База закреплена на неизменяемом публичном выпуске `v2026.10.24-local-ai`: SHA исходного полного inventory и publication-assets.json, размеры, SHA и URL девяти app-assets. Проверяется малый исходный setup ZIP и точное соответствие его публичного inventory всем 6811 файлам. Большие неизменные веса, SQLite и документы повторно не упаковываются. Для чистой установки используется исходный setup с прежними закреплёнными публичными частями; существующая проверенная установка обновляется дельтой.

## Условия сборки

Команда `build` требует окончательный runtime со всеми семью модулями и отдельный JSON `--authority`. До решения root его не создавать. Обязательные поля authority:

- `state: "release-runtime-frozen"`, `approved_for_distribution: true`, `human_review: false`;
- совпадающие `configuration_id`, новый `release_tag`, точный `runtime_root`;
- `runtime_inventory` с точными `path`, `bytes`, `sha256` переданного полного stage;
- совпадающие со stage `app_sha256`, `model_manifest_sha256`, `corpus_sha256`;
- `quality_acceptance: "demonstrated"` либо `"not-demonstrated"` и непустой честный `quality_notice`.

Прежняя freeze/fallback-decision этим разрешением не является. Gate не создаёт свидетельств качества. До записи выходного каталога проверяются SHA всех целевых файлов. Выходной каталог обязан быть новым, отдельным от runtime, без reparse-предков. На C: сохраняется минимум 20 ГиБ. Упаковка потоковая; изменённые файлы повторно сверяются по SHA, размеру и идентичности во время чтения.

После утверждения окончательной сборки точные пути и новый тег подставляются в команду:

```powershell
& src/build/model-preparation/venv/Scripts/python.exe -X utf8 src/release-research/delta.py build `
  --base-inventory src/build/research-20261024/final-control-untrained-v1.stage.json `
  --base-assets D:/Mini-AI-release-20261024-foundation-v1/publication-assets.json `
  --base-setup D:/Mini-AI-release-20261024-foundation-v1/Mini-AI-setup.zip `
  --target-inventory <окончательный-stage.json> `
  --authority <утверждённый-authority.json> `
  --target-tag <новый-тег> --configuration-id <новая-конфигурация> `
  --out <новый-отдельный-каталог>
```

`plan` принимает те же пути, кроме `--authority` и `--configuration-id`; вместо каталога `--out` обозначает новый JSON плана. План не разрешает упаковку и не меняет runtime.

## Установка и восстановление

В setup находятся `Delta-Setup.ps1`, `Delta-Apply.ps1`, общие функции и закреплённый исходный foundation setup. Для пользователя предусмотрен `Установить-и-запустить.cmd`; новая установка создаётся в подпапке `App`. Для существующей папки используется `Delta-Setup.ps1 -InstallDirectory <путь>`. Требуются штатный Windows PowerShell 5.1 и интернет для недостающих файлов; отдельные Python, .NET, UAC и авторизация не нужны. Приложение закрывается до обновления.

**Обычная исходная установка имеет CPU worker.json `3217e543…`, а canonical payload — CUDA `91eef09c…`.** Оба точных профиля распознаются, backend сохраняется, новые CPU/CUDA-профили содержат SHA нового worker. Неизвестный пользовательский manifest или несовпадающий принадлежащий выпуску файл сохраняется, операция останавливается.

Проверяются полные inventories, Windows-пути, case-collisions, reparse-предки, точный состав ZIP и SHA. Case-only переименования, удаление прежних runtime-путей и переходы file/directory не поддерживаются. Неизвестные файлы пользователя не удаляются. Перед staging публикуется собственный журнал; перед каждой заменой в него записывается намерение. Замена существующего файла атомарна для одного пути, прежняя версия остаётся в backup, release metadata меняется последней. После прерывания повторяется тот же установщик: восстановление проверяет SHA и NTFS identity собственных заменённых файлов. При конфликте неизвестные версии и backup сохраняются с указанием путей. `VerifyOnly` не создаёт lock, загрузки и журнал.

Операционный lock сериализует установщик и launch wrappers. Прямой запуск EXE не соблюдает этот lock, поэтому атомарность всей многофайловой установки при внешнем запуске не гарантируется. SHA доказывает идентичность файлов, а не правильность ответов модели.

**До окончательного candidate/authority остановиться.** Затем остаются фактическая упаковка и минимальная проверка установки/обновления/восстановления полного приложения. Новые fixture-релизы и расширенные матрицы сейчас не создаются. Проверки прежнего установщика не заменяют проверку новой дельты.
