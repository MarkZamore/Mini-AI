The Visual Studio licence's DISTRIBUTABLE CODE section provides the developer
grant and its conditions. Microsoft's deployment documentation describes
release static-library object code linked into a single deployable executable.
The licensing guidance distinguishes distributing linked output from shipping
the .lib files themselves. EnterpriseAI ships no Microsoft .lib, compiler,
headers, CRT source, debug runtime, or redistributable DLL. The current web
distributable list explicitly enumerates VC/redist files; it does not separately
enumerate the static CRT .lib paths. The release static-link distribution
interpretation therefore also relies on the deployment/licensing guidance.

Release distribution remains conditional on a valid developer licence,
Community edition eligibility, absence of preview/unreleased components, added
application functionality, the required protection in distributor/end-user
terms, and the other distribution restrictions and obligations in that licence.
Including these documents is evidence, not proof that all such conditions or
the distributor's end-user agreement have been fulfilled.

GraalVM/OpenJDK modified sources retain their original GPLv2 Classpath Exception.
That exception permits executable linkage with independent modules governed by
their own terms. Microsoft CRT code is not relicensed under GPL/EPL and its
source is not included in the source archive. No Classpath Exception is removed.
This avoids claiming that the CRT becomes GPL-covered source; it is not a legal
certification of the entire distribution. SWT and other components retain their
own licences and notices. The application owner's licence is not inferred.

Static runtime servicing requires rebuilding and redistributing the application
when relevant runtime security fixes are adopted; Windows Update cannot replace
the runtime object code embedded in this EXE.
