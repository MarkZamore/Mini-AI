# EnterpriseAI

Приложение Windows x64 на Java 25 с независимыми сервисами поиска, документов, графа, локальной модели, сеанса и открытия источников. Оригиналы `docs` и существующая база `db` используются только для чтения. В приложение не включены конвертация, OCR и перестроение индекса.

Основной профиль `static` содержит нативно скомпилированный Java-код, SWT, SQLite, Windows-адаптер и статическую CRT в одном `Mini-AI.exe`. Дополнительные DLL, распаковка и установленная Java или Python не требуются. Используются системные компоненты Windows. Публикация разрешена только после испытаний конкретного EXE; статус и контрольные суммы находятся в `VERIFICATION.md`.

## Запуск и перенос

Для переноса статического профиля скопируйте `Mini-AI.exe` и папки `docs`, `db`, `model`. Папка `src` и её результаты сборки получателю не нужны. Пути определяются по фактическому EXE, независимо от рабочей папки и ярлыка. Лицензии, notices, состав компонентов и соответствующие исходники встроены в EXE; команды `--licenses` и `--component-inventory` выводят тексты из памяти. Команда `--third-party-source-stdout` передаёт ZIP-архив через stdout без создания файла приложением.

Модель готовится отдельно на мощной машине по [instructions.md](../model/instructions.md). Комплект `model` содержит самостоятельный `inference-worker.exe`, `worker.json`, веса и обычные сопутствующие данные; дополнительные DLL и EXE запрещены. Чтобы сменить мощность или движок, закройте приложение и замените папку `model` целиком. Без модели граф и независимые функции продолжают работать.

При подготовке новой копии данных сохраняйте `docs` целиком, а в `db` — `index.sqlite`, `documents`, `artifacts`, неизменные `catalog.json`, `report.json`, `README.md`, `schema`. Старые `db/_runtime`, `__pycache__`, тесты и Python-инструменты конвертации приложению не нужны и в новую поставку не включаются; оригинальную папку они не удаляют. В `model` первоначально находится инструкция, позднее — проверенный комплект модели. Сборка staging содержит только файлы приложения, поэтому перенос данных выполняется отдельно. Права распространения самих документов проверяются отдельно от лицензий программных зависимостей.

При запуске из очень глубокого пути рабочая папка запуска должна оставаться короткой, например `C:\Windows`: Windows может отклонить создание процесса, если сама рабочая папка длиннее MAX_PATH. Для ярлыка задайте такую папку в поле «Рабочая папка» / Start in. Приложение после запуска всё равно ищет данные по расположению EXE. Это [ограничение CreateProcessW в Windows](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setcurrentdirectory); перенос самого EXE в путь длиной 380 символов отдельно испытан.

Для проверки доступны команды `--status`, `--commands`, `--search "запрос"`, `--get-fragment ID`, `--graph`, `--neighbors ID`, `--resolve JSON`, `--model-status`. Точные команды присутствующего состава возвращает `--commands`.

Поиск распознаёт обычные вопросительные формулировки: удаляет служебные слова и учитывает русские склонения также в заголовках существующего индекса. Смысловые слова, даты и коды остаются обязательными. Вопросы об организации ищут общие признаки полного наименования/юридической формы в тексте документов и возвращают до трёх исходных фрагментов; конкретная организация не задана в программе. Короткие запросы по ключевым словам сохраняют прежний порядок и состав результатов. Перестроение базы не требуется.

Каждый запрос помощника получает собственные короткие номера источников в контексте модели. Потоковые цитаты переводятся в исходные идентификаторы перед передачей интерфейсу; незавершённые и неизвестные ссылки отклоняются. Исходные фрагменты и история сохраняют канонические идентификаторы. Ограничения извлечения добавляются приложением после краткого ответа.

На испытанной Windows 11 build 26200 служба ввода Windows аварийно завершает окно при длине пути EXE от 256 символов UTF-16. В таком случае самостоятельное приложение включает для своего потока интерфейса режим совместимости и показывает предупреждение. Обычный ввод русского, казахского и Unicode сохраняется; составной ввод через IME недоступен. Настройки Windows не изменяются. При коротком пути этот режим не включается. Команды без интерфейса и поток интерфейса принимающего Java-приложения не получают его автоматически. Явное открытие собственного диалога Open With отдельно подготавливает вызывающий диалог поток. Для полного IME используйте короткий путь самого EXE; документы и модель могут находиться глубоко внутри папок данных.

Интерфейс содержит помощника слева и граф справа, перетаскиваемый разделитель, масштабирование и перемещение графа. Одинарный клик выбирает узел и показывает название внизу окна; двойной клик проверяет оригинал и предлагает внешнюю программу через Windows Open With. Для просмотра оригинала нужна подходящая программа на компьютере; встроенного PDF/Office-просмотрщика нет.

## Сборка

Все исходники, конфигурация, тесты и инструменты подготовки находятся в `src`; промежуточные файлы и кеши — в `src/build`. Разработчику нужны GraalVM CE 25.0.2+10.1, MSVC 14.51.36231, Windows SDK 10.0.26100.0, Python для сборочных сценариев и Cygwin для архивов OpenJDK. Сборочная среда не входит в поставку. Подготовка статического toolchain описана в `toolchain/README.md`.

```powershell
.\build.ps1 -Action build -Profile static
# Публикация разрешена после испытаний конкретного EXE.
.\build.ps1 -Action publish -Profile static
```

Локальное исправление поиска собрано в профиле `native` с DLL рядом с EXE, поскольку прежний статический toolchain здесь отсутствует. Для него отдельно проверяются поиск и запуск интерфейса; старые свидетельства статической сборки не подтверждают эту новую сборку. Профиль `jvm` (`jpackage --type app-image`) остаётся инструментом разработки. Установщик и самораспаковка приложения не используются.

Обычный запуск этого профиля испытан. В испытанной версии launcher `jpackage` не находит включённую JVM при очень длинном пути образа; этот профиль пока не прошёл приёмку длинных путей и не опубликован как основная поставка.

```powershell
.\build.ps1 -Action build -Profile jvm
```

`publish` переносит только принадлежащие приложению файлы из `build/staging/EnterpriseAI` в корень проекта. Существующие `docs`, `db`, `model` он не копирует, не удаляет и не перезаписывает. Статическая публикация проверяет `build/test-results/static-release-acceptance.json`; резервная копия прежних файлов и журнал публикации остаются внутри `src/build`.

## Контракты и модули

Обязательное ядро: `contracts`, `bootstrap`, `shell`, `platform-windows`; SWT и статические нативные компоненты интерфейса. Необязательные папки: `database`, `documents`, `search`, `graph`, `inference`, `assistant`, `sources`. В `module.json` указаны ID, версии, фабрики сервисов и интерфейса, предоставляемые и требуемые контракты. Сборка обнаруживает присутствующие папки автоматически.

После удаления необязательной папки выполните чистую пересборку:

```powershell
.\build.ps1 -Action clean
.\build.ps1 -Action build -Profile static
.\build.ps1 -Action publish
```

Генерируемый каталог, классы, команды, интерфейс, ресурсы и собственные зависимости удалённого модуля не включаются. Отсутствие нужного сервиса отключает зависимую возможность. Стабильные Java-контракты остаются в ядре. Нативный EXE имеет фиксированный при сборке состав; добавление нового JAR требует пересборки.

Бизнес-части не импортируют SWT. `EnterpriseAIComponent.create(environment, modules, panels)` позволяет встроить компонент в другое Java-приложение. Корень данных задаёт принимающее приложение. Графическое встраивание требует SWT-совместимого host. При закрытии компонент освобождает переданные ему executor и platform; нескольким независимым экземплярам нужны отдельные среды. SWT Display и окно принимающего приложения остаются у host. Независимые JAR ядра, контрактов, сервисов и интерфейса находятся после сборки в `build/modules`.

## Данные и модель

SQLite 3.53.1 с FTS5 открывается только для чтения. Собственный VFS отклоняет записи и создание побочных файлов; временные SQL-структуры находятся в RAM. `immutable` и восстановление журналов не используются. Unicode casefold, нормализация и русский Snowball проверены относительно существующего Python-поиска; Python не используется приложением.

Граф показывает все документы, включая изолированные. Рёбра строятся только по подтверждённым целям. Повторы не увеличивают число уникальных соседей; самоссылки не увеличивают размер. Радиус в DIP: `min(56, 16 + 6 * sqrt(degree))`. Центральное притяжение, отталкивание и пружины связей формируют круглое облако. При перетаскивании узел удерживается указателем и тянет соседей; после отпускания движение затухает. Камера при этом остаётся неподвижной. Перемещение более 5 DIP подавляет открытие оригинала; Escape и потеря фокуса освобождают узел.

Физика вычисляется в отдельном потоке, неподвижная сцена перестаёт расходовать вычисления. Интерфейс получает последние готовые координаты, очередь кадров не накапливается. Раскладка и кеши хранятся в памяти. Canvas использует обычный GDI без сглаживания: на существующих 599 узлах этот способ заметно сокращает время отрисовки. Радиусы, точность выбора узлов и состав графа от этого не меняются.

Модель не загружается при старте. На отправке проверяются manifest, SHA-256, CPU и свободная память. Приложение не скачивает веса, не обучает модель и не меняет точность или контекст автоматически. Автономный `inference-worker.exe` работает в отдельном Job Object; обмен идёт через анонимные UTF-8 JSONL-каналы. Протокол и JSON Schema находятся в `modules/inference/resources`.

История живёт до закрытия компонента. Отсутствие провайдера или модели, отмена и ошибки отображаются в помощнике. Текст документов и ответы модели не дают доступа к запуску команд. При замене совместимого набора `docs/db` ответы опираются на новые предоставленные фрагменты; смена набора выполняется при закрытом приложении.

## Источники и граница гарантий

Перед открытием проверяются фактический путь внутри `docs`, наличие оригинала и SHA-256 версии. Цепочка производных артефактов проверяется отдельно. Внешний просмотрщик не гарантирует переход к странице, ячейке или XPath. Координаты производного документа не выдаются за координаты оригинала.

Внешняя программа может записывать настройки, кеши и изменять открытый оригинал. Приложение не защищает файл от редактирования сторонним просмотрщиком. При отсутствии программы отображается сообщение; ничего не устанавливается.

История, настройки, кеши и диагностика приложения находятся в RAM. Извлечение DLL отключено в изменённом загрузчике SWT. Записи SQLite блокируются. Действия Windows, защитного ПО, драйверов, подкачки, внешних программ и средств испытаний имеют отдельную границу ответственности.

Результаты проверки конкретного `Mini-AI.exe` на этом ноутбуке перечислены в [VERIFICATION.md](VERIFICATION.md). Аудит Process Monitor пропущен по прямому решению пользователя; он исключён из будущего обязательного конвейера и условий публикации. Снимки файлов и анализ кода не подтверждают отсутствие кратковременных файлов и реестровых операций, поэтому для текущей сборки такое подтверждение не заявляется. Прежние трассы относятся к другим SHA EXE. Проверки чистой Windows и реальной модели остаются отдельными этапами. [Матрица испытаний](tests/portability/README.md) описывает текущие проверки. Не используйте `db/validate.py` для приёмки: он изменяет существующие отчёты базы.
