# Проверка EnterpriseAI: самостоятельный основной EXE

Дата отчёта: 15 октября 2026 года. Основные испытания и захват Process Monitor выполнены поздно 14 октября; последующий разбор завершался 15 октября. Компьютер: ASUS Zenbook Duo UX8407AA, Windows 11 Home x64 build 26200, Intel Core Ultra X9 388H, 32 ГБ памяти. Это компьютер разработки, а не чистая Windows.

**Проверка текущей цели завершена.** Точная испытанная сборка опубликована в корне проекта; состав поставки и неизменность исходных данных повторно проверены. Настоящая модель и чистая Windows исключены из текущей цели по решению пользователя.

Этот итоговый отчёт оформлен после публикации. Снимок 177 исходных файлов, JAR и нативных архивов проверен до замены EXE; последующее изменение `src/VERIFICATION.md` касается только документации и не меняет исполняемый файл.

## Конкретная сборка и поставка

- Опубликованный файл: `../EnterpriseAI.exe`, **315 445 248 байт**, около 300,83 МиБ.
- SHA-256: `d91c382397ea528e55689b123781137849694701bc12f10c767cfb94ba800764`.
- Основной код остаётся Java 25 с SOA-сервисами и SWT. Используется закреплённая изменённая сборка GraalVM CE 25.0.2; необходимые нативные архивы JDK/SVM, CRT, SWT, Windows-адаптера и SQLite связаны статически. Установленные Java, Python и VC Runtime при запуске не требуются.
- Программная часть настольной поставки — один `EnterpriseAI.exe`. DLL приложения и среды выполнения не поставляются и не извлекаются при запуске. Входящие в Windows библиотеки разрешены и действительно загружаются.
- Рядом остаются `docs`, `db`, `model`. Данные определяются относительно фактического EXE, а не текущей рабочей папки или ярлыка.
- Для смены модели и движка разрешён отдельный самостоятельный `model/inference-worker.exe`, обычные файлы весов, manifest и необходимые данные. После подготовки модели комплект будет содержать два EXE. Любая DLL и дополнительные EXE в модельном пакете запрещены; совместимость формата, CPU и памяти проверяется до использования.
- `src/build` исключён из поставки. Java-артефакты для встраивания — отдельные результаты разработки, а не зависимости настольного EXE. Старый `db/_runtime`, Python-конвертеры и OCR-инструменты приложению не нужны; они не запускаются и не удаляются из исходного проекта.

Опубликован точный принятый EXE; прежние принадлежащие приложению DLL, `native` и внешние `licenses` удалены по проверенному перечню. Резервная копия находится внутри `src/build/publication` и не входит в поставку. [Публикация](build/test-results/static-publication.json), [независимый итоговый состав](build/test-results/static-publication-inventory.json).

На данной Windows у очень длинного фактического пути EXE сохраняется обход ошибки системного TextInputFramework: для принадлежащего приложению UI-потока отключается IME-композиция, а интерфейс сообщает ограничение. Обычный ввод русского, казахского и emoji проверен. Длинная текущая рабочая папка может быть отклонена самим `CreateProcessW` ещё до запуска приложения; проверка длинного EXE использует допустимую рабочую папку. Это ограничение Windows не обходится временной копией приложения.

Открытие оригиналов выполняется через Windows Open With после проверки пути и SHA-256. Наличие Office или просмотрщика не предполагается: при отсутствии подходящей программы показывается ошибка. Общий диалог Windows не гарантирует переход к конкретной странице, ячейке или XPath. Внешний просмотрщик может создавать собственные записи и изменять оригинал; его поведение не включается в гарантию контролируемых компонентов.

## Данные, лицензии и границы подтверждения

Базовая проверка охватывает состав, размеры и времена изменения **28 230 файлов `docs/db`**. Из них **7 894 файла** дополнительно проверяются SHA-256; **20 336 файлов старого `db/_runtime`** проверяются только по метаданным. Неизменность их содержимого по полному SHA не заявляется. Исходные JSON, документы, индекс и история базы не перестраиваются и не исправляются приложением.

Исходный SQLite SHA-256: `58d6d60adbe58e4e9fe17ba0e843d40bc56906bd1dde9a7b2d12276401d7399a`. Проверка источников подтверждает сохранение индекса; SQLite открывается read-only, временные структуры остаются в памяти. Базовые снимки: [данные до миграции](build/test-results/static-data-integrity.json), [исходный снимок](build/test-results/data-before.json).

После публикации повторно сверены 28 230 путей, размеров и времён изменения; для 7894 файлов с хешем в исходном снимке сверены SHA-256 (6,699 ГБ). Для 20 336 файлов старого `db/_runtime` сохранён исходный охват по метаданным: они не представлены как повторно хешированные. Новых/удалённых/изменённых файлов и SQLite sidecar нет; инструкция модели сохранена. [Заключительная сверка](build/test-results/static-data-integrity-postpublication.json).

Лицензии, notices, состав компонентов и соответствующие исходники встроены в EXE. Меню «Справка → Лицензии и исходники» показывает тексты из памяти. Команды `--licenses` и `--component-inventory` выводят материалы; `--third-party-source-stdout` передаёт полный ZIP без извлечения. Сохранение stdout в файл выполняет явно вызывающая программа, а не EnterpriseAI.

Архив исходников: **273 669 812 байт**, SHA-256 `40e483ed71cfe952ce484272969da24e0a8560b0ebe715f2c8fa087a8309f52b`. Проверены 119 исходных материалов, 269 notices, оба закреплённых upstream SHA и соответствие 115 локальных файлов встроенным копиям: [нaтивная проверка лицензий](build/test-results/static-native-licenses.json), [проверка меню](build/test-results/static-procmon/final-20261014-d91c3823/legal-ui.json). Большая часть размера EXE приходится на поставку соответствующих исходников.

GraalVM/OpenJDK сохраняют GPLv2 Classpath Exception, SWT — EPL 2.0; применимые third-party notices сохранены. Для статического CRT записаны отдельные условия Visual Studio 2026 и обоснование распространения: лицензия получателя runtime сама по себе не выдаёт права разработчику распространять код. Условия действующей лицензии разработчика, применимость Community и защита Microsoft Distributable Code в соглашении с конечным пользователем остаются обязанностями распространителя; наличие встроенных материалов не объявляется юридической сертификацией поставки. Для будущего worker и весов нужен отдельный проверенный лицензионный комплект.

Подтверждение относится к конкретной сборке, указанным сценариям и данной машине. Windows, системная подкачка, защитное ПО, драйверы и внешние программы могут выполнять собственные записи. Хранение сеанса в RAM не обещает отсутствия следов в подкачке или системных дампах.

Поддерживаемая целевая ОС — Windows 11 x64. Проверена машина с 32 ГБ; минимум 8 ГБ для оболочки/поиска/графа остаётся предварительной целью и не подтверждён испытанием малой памяти. История хранится до завершения сеанса и после перезапуска отсутствует.

Настоящие веса, обучение модели на мощной машине и испытание чистой Windows без средств разработки по решению пользователя находятся вне текущей цели. Тестовые worker подтверждают смену движка, протокол и аварийную изоляцию, но не качество языковой модели, её скорость, память или фактическую загрузку на ноутбуке. Такие показатели объявляются только после измерений готового модельного комплекта.
